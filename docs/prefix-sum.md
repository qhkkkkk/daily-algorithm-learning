## 前缀和与区间和

P[t] 表示前 t 个元素之和，P[0] = 0。注意 t 是元素数量，P[t] 不包含 nums[t]。

```text
nums = [2, 3, 4]
P    = [0, 2, 5, 9]

下标 [1, 2] 的和：
P[3] - P[1] = 9 - 2 = 7
```

下标闭区间 [left, right] 的和为 P[right+1] − P[left]。减去开头完整的一段，剩下的是连续区间；这里没有跳着挑选元素。

如果要重复查询指定区间的和，可以先花 O(n) 时间建立 P 数组，之后每次查询只需一次减法。辅助数组占 O(n) 空间。

## 从求和到计数

如果题目要求“有多少个连续子数组的和为 k”，可以逐个固定终点：

```text
P[right+1] - P[left] = k
P[left] = P[right+1] - k
```

扫描时维护当前前缀和 prefix，用 counts 保存此前前缀和值的出现次数。每一轮固定同一个终点；满足条件的旧前缀出现几次，就有几个不同起点。

以 [1, -1, 1]、k = 1 为例，前缀和依次为 0、1、0、1。读到最后一个 1 时，当前前缀和为 1，需要旧前缀和为 0。此前 0 出现两次，分别对应整段 [1, -1, 1] 与最后一个 [1]。本轮新增 2；加上第一轮的 [1]，总答案为 3。

字典只保存频次就足以回答“数量”，无需保存每个子数组。如果要返回区间本身，则还需保存边界位置，不能只用这一份计数表。

## 两条初始化与顺序规则

```python
prefix = 0
ans = 0
counts = {0: 1}

for num in nums:
    prefix += num
    need = prefix - k
    ans += counts.get(need, 0)
    counts[prefix] = counts.get(prefix, 0) + 1
```

第一条：初始空前缀和 0 出现一次。否则会漏掉从下标 0 开始的答案，例如 [2, 3]、k = 5。

第二条：先查旧前缀，再记录当前前缀。这样旧边界总在当前终点之前，区间非空。若先记录，k = 0 时当前前缀会匹配自己，把空区间误算成答案。例如 [1]、k = 0 的正确结果是 0。

每次查询前，表中只有此前的前缀边界。每次记录后，当前边界才会用于下一轮。

## 与其他方法的区别

以下是补充讲解：

| 方法 | 保存的信息 | 本题需要注意 |
| --- | --- | --- |
| 暴力枚举区间 | 当前起点和终点之间的和 | 易理解，可用作小输入的独立验证，O(n²) |
| 前缀和数组 | 每个边界对应的累计和 | 求单段和快，但枚举全部两端仍有 O(n²) 对 |
| 前缀和加哈希频次 | 旧前缀和值及出现次数 | 平均 O(n) 时间，O(n) 辅助空间 |
| 集合 | 某个值是否出现过 | 无法区分旧前缀出现一次还是多次，会少计答案 |
| 按区间和大小收缩的滑动窗口 | 当前窗口及其和 | 负数破坏简单的单调关系，不能直接照搬 |

[2, -1]、k = 1 就是滑动窗口直觉的反例：读到 2 时若立即因“超过 1”而删除它，会错过后面的整段 [2, -1]。

第 1 题“两数之和”查的是旧元素值，通常返回两个下标；第 560 题查的是旧前缀和值，统计连续区间数量。虽然都可用哈希表，键和值的含义不同。
