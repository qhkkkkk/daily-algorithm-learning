## 运行方法

运行实际题解源码，不复制算法到测试中。需要 Python 3、Java/Javac、GCC/G++：

```bash
python tests/verify.py --require-all
```

可通过 --cc、--cxx 指定编译器路径，也支持 CC/CXX 环境变量。Windows 路径含空格时用引号括起，例如：

```text
python tests/verify.py --require-all --cc "D:/tools/mingw/bin/gcc.exe" --cxx "D:/tools/mingw/bin/g++.exe"
```

不加 --require-all 时，缺失语言会明确打印 SKIP；只看到部分语言通过，不代表全部语言都已验证。

## 覆盖范围

- 两数之和：309 组输入，包含固定边界、300 组固定随机种子的唯一解样本，以及长度 10000 的输入。
- 移动零：309 组输入，包含固定边界、300 组随机样本，以及长度 10000 的输入。
- 盛最多水的容器：1674 组输入，三种语言均与预期面积比较并检查输入未被修改。包含 11 组固定用例、长度 2～5 且高度取 0～3 的全部 1360 种数组、300 组固定种子随机数组、3 组长度 100000 的输入。
- 三数之和：每种语言 1500 组输入，包含 15 组固定用例、长度 3～6 且元素取 -1/0/1 的全部 1080 种数组、400 组固定种子随机样本、5 组长度 3000 的输入。覆盖连续重复值、全零、无解、数值边界与排序前的不同排列。
- 三数之和的小数组与枚举三个不同下标的暴力参考比较；先检查每组三个值及其输入出现次数，再检查结果唯一性和完整性。不会把结果先转集合而漏掉重复答案。大数组采用可直接推导的预期结果，Python 额外检查输入确实被排序。测试入口为 tests/three_sum_check.py。
- 无重复字符的最长子串：每种语言 3604 组输入，包括 20 组固定用例、字符集 abc 上长度 0～7 的全部 3280 种字符串、300 组固定随机种子的样本、4 组长度 50000 的输入。覆盖空串、单字符、空格、大小写、连续重复、中间重复和错误删除右端字符的反例。小输入枚举每个子串独立检查唯一性，大输入使用可直接推导的预期值；测试入口为 [substring_check.py](substring_check.py)。
- 字符串测试使用长度与字符编码传输输入，保留空串、空格、引号和反斜杠。跨语言样本限定 ASCII 范围，未将其声称为任意 Unicode 文本验证。
- 第 438 题字母异位词：每种语言 4100 组输入，包含 14 组固定例子、二元字母表 ab 上 s 长度 1～6 与 p 长度 1～4 的全部 3780 对组合、300 组固定随机种子的样本、6 组最大长度边界用例。覆盖重叠答案、重复字母、首尾窗口、p 更长、m=1、n=m、a/z 映射边界与大量匹配。
- 异位词题的小输入逐个枚举子串并排序，与计数更新算法独立；大输入用可推导的起点列表比较。结果先检查下标合法性与重复记录，再比较完整答案。该题输入非空且只有小写字母，测试入口 [anagram_check.py](anagram_check.py) 使用直接字符串传输；不将第 3 题的编码输入要求套到此题。
- 容器题的小数组预期值由枚举全部下标对的暴力方法产生；大数组使用可直接计算的预期值，覆盖等高、两端高而内部为零、仅一端高的情况。测试入口见 tests/container_check.py，由 verify.py 统一调用。
- 两数之和检查返回位置合法、互不相同且和正确，允许答案下标顺序不同；Python 额外检查输入未被修改。
- 移动零与“保持非零顺序再补零”的参考结果比较；Python 额外检查返回 None。
- C 的两个实现额外检查无解时返回 NULL 且输出长度为 0，这属于题目保证有解之外的防御性扩展。
- C11 / C++17 编译开启 -Wall -Wextra -Werror -pedantic。
- Java 的每个 Solution 独立编译，避免类名冲突。
- 检查仓库内 Markdown 文件链接、内部锚点、题解完整代码块与源码的一致性。

临时测试入口与二进制在临时目录生成并自动清理，不写入题解源码。这里没有模拟内存分配失败，也不以这些样本证明所有输入均正确；正确性说明见各篇题解。
